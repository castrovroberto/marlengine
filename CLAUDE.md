# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Marlengine is a personal C++17 game engine (following The Cherno's engine series). Two Premake projects: `Marle` (the engine, built as a shared library) and `Sandbox` (a demo client that links it: `WorldLayer` is a tiled world with a player, camera and sprite sheet loaded from the scene file `Assets/Scenes/world.json` (it moves the entities named camera, player, satellite and spinner_0 to spinner_3 by writing their Transforms each frame; the `Tilemap` entity `world` is its map) and drawn by a `SceneRenderer`, rendered into an `OpenGLFramebuffer` shown in an ImGui "Viewport" panel (straight to the window when the panel is closed or there is no `ImGuiLayer`); `HudLayer` is a pixel-space input overlay with a zoom readout and a hint line drawn with `BitmapFont`; `StatsLayer` is an ImGui panel with frame time, renderer stats and camera values; WASD/arrows move, Shift runs, Q/E rotate the camera, wheel zooms, R resets, H toggles the HUD, F1 toggles the stats panel, F2 toggles the viewport panel, F3 the scene panel, Esc quits; editing `world.json` while it runs reloads the world). The only tests are the `Tests/` projects (below); there is no linter.

Direction: worlds, characters and interactions are meant to be plain-text data that an AI can write and git can diff (scene files loaded through a component registry, entt behind our own `Scene`/`Entity`). See `docs/adr/0001-scenes-are-text-data-on-entt.md`; entity behavior follows `docs/adr/0002-behavior-is-a-fixed-set-of-deterministic-data-components.md` (a fixed set of engine-provided behavior components, configured in scene files and run deterministically: same scene, seed and input recording give the same result; milestone M6, not yet implemented); project vocabulary is in `GLOSSARY.md`.

## Build & run

- Makefiles are generated by Premake (`premake5.lua`) and are gitignored. `./r.sh [config]` regenerates, cleans and builds (default `debug`). It uses `premake5` from PATH if present, else `vendor/premake5`, which is a tracked Linux x86-64 binary only.
- Build: `make config=debug|release|dist` (default `debug`); single target: `make Marle` or `make Sandbox`. Output goes to `bin/<Config>-<system>-<arch>/<Project>`.
- Run Sandbox from the repo root, since it loads assets via relative paths (`Assets/...`): `./bin/Debug-linux-x86_64/Sandbox/Sandbox` (rpath finds `libMarle.so`). stdout is block-buffered when piped; use `stdbuf -oL` to see logs live.
- `marle-scene` (`make SceneTool`) checks and tidies scene files from the command line: `./bin/Debug-linux-x86_64/SceneTool/marle-scene validate Assets/Scenes` (see `docs/scene-format.md`).
- Tests (each is its own executable in `Tests/<Name>/src/`, declared with `testProject` in `premake5.lua`; they exit non-zero on failure, `make` builds them with the other targets, and there is no way to run a single check). Run from the repo root as `./bin/Debug-linux-x86_64/<Name>/<Name>`:
  - `Renderer2DTests`: needs a display and GL 3.3; draws with `Renderer2D` and checks pixels via `glReadPixels` and batching via `GetStats()`; it also checks `SceneRenderer` by drawing the same picture through `Renderer2D` and comparing pixels. Image-format fixtures (PNG, JPG, gray+alpha, truncated) live in `Tests/Renderer2DTests/fixtures/`; it also covers framebuffers and text.
  - `ApplicationTests`: needs a display; checks `Application` drives layers in order and detaches them while the GL context is alive.
  - `ImGuiLayerTests`: needs a display; checks `OnImGuiRender` runs on every layer, Marle events reach ImGui IO (mouse y-flip, capture, keys), and ImGui output via `glReadPixels`.
  - `InputTests`, `LayerStackTests`, `LogTests`, `SceneTests`: headless. `SPDLOG_LEVEL=MARLE=trace,APP=error ./…/LogTests` checks the environment override instead of the defaults.
- Submodules (`git submodule update --init`) are needed for glm; GLFW is vendored in-tree.
- Re-run Premake after changing `premake5.lua` or adding/removing files (sources are globbed: `.h`, `.cpp`, `.mm`, plus `Marle/vendor/glad/src/**.c`). Platform dirs (`Platform/Linux`, `Platform/macOS`) are excluded per target in `premake5.lua`.

## Architecture

- **Client contract**: `Marle.h` is the single include for clients. `Marle/EntryPoint.h` is separate and defines `main()`; include it in exactly one source file (the one defining `Marle::CreateApplication()`, which the client must provide). `main` calls `Log::Init()`, then `CreateApplication()`, `Run()`, and deletes the app.
- **Application** (`Application.h/.cpp`): platform-neutral. Owns a `std::unique_ptr<Window>` and a fixed-timestep loop (60 Hz, accumulator + interpolation alpha, `steady_clock`). Clients subclass it and override `OnUpdate(fixed_dt)`, `OnRender(alpha)`, `OnEvent(Event&)` and `OnResize`. The window's event callback goes to a private `HandleEvent`, which handles close, resize and Escape-to-quit before calling the client's `OnEvent`.
- **Window abstraction** (`Window.h`): abstract `Window` (`OnUpdate` pumps events and swaps buffers; `SetEventCallback`; static `Window::Create` defined once per platform). Creating a window leaves a GL 3.3+ context current with glad loaded. Mouse coordinates are bottom-left origin.
  - Linux: `Platform/Linux/LinuxWindow.cpp` (GLFW, X11 backend, vendored in `Marle/vendor/glfw`) and `LinuxKeyCodes.cpp` (GLFW key to `Marle::Key`).
  - macOS: `Platform/macOS/MacOSWindow.mm` (Cocoa/NSOpenGL), `MarleGameView.mm`, `MacOSKeyCodes.mm`. Not compiled or tested on Linux. Windows has no backend.
- **Platform macros**: `MRL_PLATFORM_*` are defined both by Premake and by `Core.h` (guarded). `Core.h` also defines the `EXPORT`/`IMPORT` visibility macros needed because the engine is a shared lib.
- **Input**: `Input::IsKeyPressed/IsMouseButtonPressed/GetMousePosition` are polled state derived from window events. `InputFrame` (`InputFrame.h`) is what the player's input was during one fixed step (keys `Down`, keys `Pressed` since the previous frame, vertical `Scroll`; `Press/Hold/Release` build one by hand): `Input::TakeFrame()` makes it from the polled state plus the presses and wheel movement since the last call (repeats are not presses; focus loss drops pending ones; with several fixed steps in a rendered frame only the first sees the new presses), `Application` calls it once per fixed step through the protected virtual `SampleInput()` (override it to feed recorded input) and exposes the result as `GetInputFrame()`; behaviors must read that and never poll. `Core/KeyNames.h` maps scene-file key names (`W`, `Space`, `LeftShift`, `F5`, `RightBracket`, exact case) to `Key` codes: `KeyName`, `KeyFromName`, `KeyNames()` (for `.OneOf(KeyNames())`). `Application::HandleEvent` feeds every event to `Input::OnEvent` before the client's `OnEvent`; state is cleared on `WindowLostFocusEvent`. Mouse buttons are `Marle::Mouse::*` (macOS only reports Left/Right).
- **Layers**: `Layer` (`OnAttach/OnDetach/OnUpdate/OnRender/OnEvent`) objects live in a `LayerStack` owned by `Application` (`PushLayer`, `PushOverlay`, `PopLayer`; overlays sit above layers; the stack owns layers via `unique_ptr`). Per frame, the app's own `OnUpdate`/`OnRender` run first, then layers bottom-to-top. Events go to engine handling and `Input`, then layers top-to-bottom until `e.IsHandled()`, then `Application::OnEvent`. Layers are detached (top first) in `~Application` before the GL context is torn down. Don't push or pop from inside a layer callback. `ImGuiLayer` (`ImGui/`) is a debug overlay: push it last with `PushOverlay(std::make_unique<ImGuiLayer>(GetLayerStack()))`. Each frame it begins an ImGui frame, calls `Layer::OnImGuiRender()` on every layer in the stack (put ImGui calls there), then draws. ImGui windows move by their title bar only. It translates Marle events into ImGui IO itself (no GLFW backend, so macOS works the same) and marks mouse/keyboard events handled when ImGui wants them (a layer showing a picture of the world calls `ImGui::SetNextFrameWantCaptureMouse(false)` while that picture is hovered so the wheel still reaches the world), but polled `Input` is fed before layers and is not blocked by ImGui capture. `Application::Close()` ends the loop.
- **Scenes** (`Scene/`): `Scene` is a named collection of entities, stored in entt, which clients never see (`Scene/SceneState.h` is internal). `Scene::CreateEntity(name)` needs a name that is non-empty and unique within the scene, otherwise it logs and returns an invalid `Entity`; `FindEntity`, `DestroyEntity`, `GetEntities()` (creation order) and `ForEach<Components...>(fn(Entity, Components&...))` (unspecified order; don't create or destroy inside it). `Scene::GetRandom()` is the scene's `RandomGenerator` (`Scene/RandomGenerator.h`, header-only PCG32 with our own `Below`, `IntBetween`, `NextFloat`, `FloatBetween`, `Chance`; never `std::` distributions, whose results differ between standard libraries; verified against an independent implementation): it starts from the `Random.seed` of the scene's own components (1 if none; negative seeds are their 32-bit value), loading a scene resets it (`ResetRandom()`), and it is runtime state, so a saved scene restarts its sequence. `Scene::GetSceneEntity()` is the scene's own entity, carrying components that belong to the scene as a whole (the top-level `components` object of a scene file, same rules as an entity's); it is not in `GetEntities()` or `GetEntityCount()`, is skipped by `ForEach`, cannot be destroyed and is named "(scene)". `Entity` is a small copyable handle (`Has/TryGet/Get/Add/Remove<T>`, `GetName()`); it goes invalid when its entity is destroyed or its scene is gone, and every operation on an invalid handle is safe (queries say no, the rest log and use a scratch component not stored anywhere). Components are plain default-constructible structs. The engine never throws or asserts: misuse is logged. `ComponentRegistry` (`Scene/ComponentRegistry.h`) names the components scene files may use: `Register<T>(name, description).Field(&T::member, "fieldName", "description")` with optional `.Required()`, `.Min()`, `.Max()`, `.Range()` per field (types: bool, int, float, string, vec2, ivec2, vec4, string[]; `.AssetPath()` marks a string as a file path; `.EntityReference()` marks a string as the name of another entity (checked by the loader once every entity has loaded, so forward references work; a missing one is a problem reported after the others with a did-you-mean, the component still loads, strict reload refuses it, the writer refuses to write one; empty means none; not combinable with `.AssetPath()` or `.OneOf()`); `.OneOf({...})` limits a string to a fixed set (errors list the allowed values, or just their number when there are more than 12, and suggest the closest; the schema gets an `enum`; the set must be non-empty, without repeats and contain the field's default, else it is logged and ignored); `.Validate(fn)` adds a check that spans fields and runs once every field read fine; a field's default is the value in a default-constructed `T`). `Read(entity, name, json)` validates and adds a component and returns every `ValidationError` (JSON path plus message; unknown fields get a did-you-mean and the list of valid fields); with any error nothing is added. `Write(entity, name, skipDefaults)` gives the fields in declaration order, floats as the shortest text that reads back identically. `RegisterBuiltinComponents` registers `Transform`, `SpriteRenderer`, `Camera`, `Tilemap` and `Random` (the scene-level seed) (`Scene/Components.h`; rotation is radians, counter-clockwise; a `Tilemap` is a grid of sprite sheet cells written as rows of base-36 characters, listed top to bottom, `.` for no tile). Data is `Json` (nlohmann `ordered_json`, parsed with comments allowed). Scene files are specified in `docs/scene-format.md` (list of named entities, components keyed by registry name, every field written, no generated ids) with a worked example at `Assets/Scenes/example.json`; `SceneTests` checks both against the registry. `LoadScene(file, registry)` / `LoadSceneFromText(text, source, registry)` (`Scene/SceneLoader.h`) return a `SceneLoadResult`: the `Scene` (null only if the file as a whole is unusable) plus every `SceneProblem` (file, JSON Pointer, message); the offending component or entity is skipped, a missing asset file is reported but the component loads, asset paths (fields marked `.AssetPath()`) must stay inside the working directory, and repeated JSON keys are errors. No GL context needed. Fixtures for each error kind are in `Tests/SceneTests/fixtures/`. `SaveSceneToText(scene, registry, options)` / `SaveScene(scene, registry, file, options)` (`Scene/SceneWriter.h`) write the canonical form (creation order, registration order, every field, one line per component, shortest floats; `Tests/SceneTests/fixtures/canonical.json` is the example without its comments and must round-trip byte for byte, so regenerate it if the example changes). What is written always reads back: anything a file cannot hold is returned as `Problems` and nothing is written (`SaveScene` replaces the file via a temporary file and leaves the old one on failure). `GenerateSceneSchema(registry)` / `SceneSchemaToText(registry)` (`Scene/SceneSchema.h`) generate the JSON Schema (draft-07) for scene files; the committed copy is `Assets/Scenes/scene.schema.json` (`$schema` in a scene points editors at it). `SceneTests` validates scenes against it with json-schema-validator (`Tests/vendor/`, test-only, compiled into that one project through the `extra` argument of `testProject`) and checks it agrees with the loader. Run `MARLE_UPDATE_GOLDEN=1 ./bin/Debug-linux-x86_64/SceneTests/SceneTests` from the repo root to regenerate the schema and `fixtures/canonical.json` after changing a component or the example. `RunSceneTool(args, registry, out, err)` (`Scene/SceneTool.h`) is the command line behind `marle-scene` (`tools/marle-scene`, Premake project `SceneTool`, built by `make` into `bin/<Config>-.../SceneTool/marle-scene`): `validate <file|dir>...` prints every problem and exits 1 if any, `format [--check] [--drop-comments] [--schema <path>]` rewrites to canonical form (refuses a file with problems, leaves a file with comments alone without `--drop-comments`, keeps `$schema`), `schema [--output|--check <file>]`; exit 2 is a bad command line. A game with its own components builds its own tool by calling `RunSceneTool` with its registry. `WriteTextFile` (`Scene/SceneWriter.h`) is the atomic file write the writer and the tool share. `SceneRenderer` (`Scene/SceneRenderer.h`, needs a GL context, destroy it while the context is alive) draws a `Scene` as one `Renderer2D` frame batch: through the first primary `Camera` (else a default one at the origin), entities in creation order so later ones are on top, each `SpriteRenderer` with a `Transform` as a flat quad, a texture or a sheet cell, each `Tilemap` as one quad per tile (a bad cell or missing sheet is the error checker); textures are loaded on first use and cached by path. `SceneReloader(file, registry)` (`Scene/SceneReloader.h`, headless) watches a scene file: `Load()` is the first load (returns whatever loaded), `Poll(force)` compares the file's modification time and size and, when they changed, loads again and hands out the new scene only if it has no problems at all (strict; otherwise the caller keeps its scene and `GetStatus()` holds the problems, `Failures` and `KeptPrevious`); a missing file is waited for. `WorldLayer` polls about six times a second, swaps the scene while keeping its simulation state (player, camera rotation, zoom, spin), logs the result and shows it in an ImGui "Scene" panel (F3, with a Reload now button). Scenes as data are done (ADR-0001, milestone M5); scripting, dialog and physics are still to be decided.
- **Events**: header-only, under `Events/` (`Event.h` with `EventDispatcher`, plus Key/Mouse/Application events). Key codes are in `Core/KeyCodes.h`, with the macOS keycode translation in `Platform/macOS`.
- **Rendering**: OpenGL loaded through vendored glad (`Marle/vendor/glad`). `Platform/OpenGL/` holds `OpenGLShader`, `OpenGLTexture2D` and `OpenGLFramebuffer` (decodes with stb_image, so PNG, JPG, TGA, BMP and the other stb formats load; always uploaded as RGBA8 and flipped so row 0 is the bottom). `Renderer/Renderer2D` is a static-API batched quad renderer: `DrawQuad` calls (textured, tinted, or flat color; `DrawRotatedQuad` adds a rotation in radians, CCW positive) fill a CPU vertex buffer between `BeginBatch` and `EndBatch()`. Positions are quad centers in world space. `SubTexture2D` (non-owning texture region; `CreateFromCoords` slices a sprite sheet by cell, row 0 at the bottom) can be passed to `DrawQuad`/`DrawRotatedQuad`. `BeginBatch(camera)` takes an `OrthographicCamera` (position, rotation, projection bounds; zoom by changing the bounds); `BeginBatch(w, h)` is pixel space, origin bottom-left, no camera., flushed in one draw call per 10000 quads or 16 distinct textures (slot 0 is a 1x1 white texture; the fragment shader selects the sampler with a switch because GLSL 3.30 forbids dynamic sampler-array indices). Quads are alpha-blended (`SRC_ALPHA`/`ONE_MINUS_SRC_ALPHA`, enabled in `Init`) in submission order with no depth test, so draw back to front; textures are straight (non-premultiplied) alpha. A texture that failed to load (`OpenGLTexture2D::IsLoaded()` false, size 0) or a null texture is drawn as a magenta/black checker; `OpenGLTexture2D` is non-copyable. Renderer errors (e.g. uninitialized renderer) are logged once, not per quad. `GetStats()`/`ResetStats()` expose draw-call and quad counts. Text: `BitmapFont` (`Renderer/`) is a fixed-width font read from a sheet of equal glyph cells in ASCII order from the top-left (space is the first cell; characters outside the sheet draw as `?`; a sheet that fails to load makes `Renderer2D` draw the error checker), and `Renderer2D::DrawString(font, text, position, glyphHeight, color)` draws one quad per glyph, `position` being the bottom-left of the first cell, `\n` starting a line below. `Assets/Fonts/mono.png` (16x32 cells) is made from DejaVu Sans Mono by `tools/make_font_sheet.py` (license in `Assets/Fonts/`). `OpenGLFramebuffer` is an offscreen target with one RGBA8 color texture (`GetColorAttachment()`, rows bottom to top, id stable across `Resize`); `Bind()` saves the current framebuffer and viewport and sets the viewport to its size, `Unbind()` restores them (nestable), and an incomplete one logs and does nothing. Draw into it with `BeginBatch(w, h)` of its size. Shaders: `Assets/Shaders/Texture.{vert,frag}`.
- **Vendored deps**: json-schema-validator (`Tests/vendor/json-schema-validator`, v2.4.1, test-only), nlohmann/json (`Marle/vendor/nlohmann`, v3.12.0 single header, scene data), entt (`Marle/vendor/entt`, v3.16.0 single header, used only behind `Scene`/`Entity`), Dear ImGui (`Marle/vendor/imgui`, v1.93.0 in-tree, core plus only the OpenGL3 renderer backend; compiled into `Marle`, symbols exported), stb_image (`Marle/vendor/stb_image.h`, v2.30, single header, implemented in `OpenGLTexture.cpp`), spdlog (`Marle/vendor/spdlog`, committed in-tree), GLFW (`Marle/vendor/glfw`, committed in-tree, Linux only) and glm (`Marle/vendor/glm`, a submodule). Logging goes through `Log.h`: spdlog-backed `MRL_CORE_*` (logger `MARLE`) and `MRL_*` (client logger `APP`) macros with fmt-style `{}` formatting, lazily initialized, default level info; raise it with `SPDLOG_LEVEL`, e.g. `SPDLOG_LEVEL=MARLE=trace` (shows every event). Engine and Sandbox code should use these, not `printf` (the `Tests/` programs print results with `printf`).
- `mrlpch.h` is the precompiled-header-style common include (pulled in by `Core.h`). Premake PCH is commented out, so it is used as a plain header.
- On macOS, `premake5.lua` adds the libc++ include dir from `xcrun --show-sdk-path` (untested on macOS).
